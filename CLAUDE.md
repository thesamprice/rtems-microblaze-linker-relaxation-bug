# Working in this repository

This repo carries patches that get **mailed to upstream maintainers** — binutils,
gcc, glibc, RTEMS. A reviewer reads the patch, not the repo. Anything sloppy in
the diff costs a round trip on a mailing list, which is measured in weeks.

## Comments next to code you modify

**Whenever you change a line, read the comments around it and check they are
still true.** A comment that describes the old behaviour is worse than no
comment: it actively misleads the next reader, and a reviewer who spots it will
send the patch back.

This is not optional cleanup — it is part of the change. Before considering a
patch finished:

1. Read the whole hunk with context, not just the changed lines. `git diff -U15`
   rather than the default three lines of context.
2. For every comment in that window, ask whether the change you just made
   falsified it.
3. Check the file for comments *elsewhere* that describe the thing you changed —
   a header block, a table, a `.exp` or `.d` file that names the target.
4. Fix them in the same patch, not a follow-up.

Look especially for:

- Lists of names that no longer match — `# mep and microblaze use ...` above an
  `#xfail:` line that no longer says `microblaze`.
- Comments explaining *why* something is disabled, xfailed, or worked around,
  when you just enabled or fixed it.
- "This is not supported on X" when you just added X.
- Grammar that breaks when a list shrinks to one item: "mep and microblaze use"
  becomes "mep uses", not "mep use".

### The one that got away

`patches/binutils/0004` removed `microblaze-*-*` from the `#xfail:` line in
`gas/testsuite/gas/all/forward.d` but left the comment above it reading "mep and
microblaze use complex relocs and don't resolve the relocs." The patch was
written, reviewed here, style-checked, A/B tested against the testsuite, and
queued to send before anyone noticed. Automated checks do not catch stale prose —
only reading does.

## How to write the message and the comments

[`patches/STYLE.md`](patches/STYLE.md) is the house style for commit
messages, cover letters and the comments inside a patch, derived from what
has actually been accepted upstream from here. Read it before writing a
patch and audit against it before sending:

```sh
python3 tools/check-patch-style.py patches/<series>
```

The checker covers subject length, prose width, the ChangeLog block, the
trailer and a list of phrasings flagged in review. It cannot tell you whether
the message is any good; the one that got away below was caught by reading.

## Other standing rules for this repo

- **Verify claims before writing them down.** Commit messages and analysis docs
  in this repo state things as fact ("no other backend does X", "this landed in
  commit Y"). Check it — `git log`, `grep` across the tree, the actual upstream
  branch — and say plainly when something was not verified.
- **Testsuite numbers must come from a run**, not from memory or from an earlier
  run of a different configuration. Build `all-ld` as well as `all-gas` before
  quoting gas results, or MicroBlaze tests that link will fail for unrelated
  reasons. See `binutils-testsuite/microblaze-elf/0004-standalone/README.md`.
- **Never hand-edit generated mails** and expect it to survive.
  `tools/make-outbox.sh` regenerates `outbox/` from `patches/<repo>/`; commit
  message and diff live in `patches/<repo>/NNNN-*.patch`, and reviewer notes go
  in `patches/<repo>/NNNN-*.notes`, which are inserted after the `---` line and
  dropped by `git am`. The `__moddi3` series is separate: `moddi3/patches/` is
  regenerated by `moddi3/make-series.sh` from `moddi3/messages/*` and
  `moddi3/harness/moddi3-fixed.S`.
- **Re-measure after touching the code, and say whose numbers they are.** The
  `__moddi3` texts quoted 56 instructions and 3,607,673 executed for months;
  those were the figures for the patch as its original author sent it, not for
  what this repo had since made of it. A number inherited from an earlier
  version of the same patch reads exactly like a measured one.
- **No local absolute paths in tracked files.** `tools/check-local-paths.sh` is a
  pre-commit hook; scrub `.sum` and log files with the documented placeholders.
- **Mailing-list patches take `Assisted-by:`, never `Co-Authored-By:`.**

This is the finding that killed the planned testsuite patch.  The upstream
test already detects the bug on both byte orders.  Its first division block is
unsigned, which is what misled an earlier pass, but a signed long long block
follows it and does exactly the right thing.  So the coverage is not missing --
the execute testsuite simply is not being run for MicroBlaze.

Notes
-----
* The two byte orders differ by 63 instructions out of 3.6 million for the
  assembly, so the #ifdef __MICROBLAZEEL__ half-naming costs nothing at run
  time; it resolves at assembly time.
* The patched routine is four instructions smaller than stock (56 vs 61): it
  drops three dead r18 comparison instructions and two redundant zero-stores
  and adds one BLTi guard.
* The counter device is DEVICE_LITTLE_ENDIAN, so a big-endian guest must
  byte-swap the 32-bit read or the delta is nonsense.  bench.c does this.
* __udivmoddi4 is shared: a program already doing 64-bit unsigned division
  links it regardless, and there the generic __moddi3 costs only 62
  instructions rather than 1092.
